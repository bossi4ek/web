# Лабораторна робота №6: Production Readiness (Безпека, Логування, Деплой)

## 1. Мета роботи
Опанувати інструменти для підготовки Node.js додатку до production-середовища. Навчитись налаштовувати CORS, обмежувати кількість запитів (Rate Limiting), додавати базовий захист HTTP-заголовків, впроваджувати професійне логування та підготувати проєкт до розгортання.

## 2. Теоретичні відомості
- **CORS (Cross-Origin Resource Sharing)** — механізм, який використовує додаткові HTTP-заголовки, щоб вказати браузеру дозволити веб-додатку, що працює на одному домені (origin), отримувати доступ до обраних ресурсів на сервері іншого домену.
- **Helmet** — набір дрібних middleware-функцій для Express, що налаштовують HTTP-заголовки для захисту додатку від деяких відомих веб-вразливостей (наприклад, XSS-атак).
- **Rate Limiting (Обмеження частоти запитів)** — підхід для контролю мережевого трафіку. Допомагає захистити API від brute-force атак та базових DDoS-атак, обмежуючи кількість запитів від одного IP-адресу за певний час.
- **Логування (Winston, Morgan)** — `morgan` використовується для логування HTTP-запитів, а `winston` є потужним логером для запису системних подій, помилок, з можливістю зберігання логів у файлах або сторонніх сервісах (наприклад, ELK).
- **Production Environment (NODE_ENV)** — змінна середовища, що вказує, у якому режимі запущено додаток (розробка, тестування чи production). Багато бібліотек (включаючи Express) оптимізують свою роботу, якщо `NODE_ENV=production`.

## 3. Завдання
1. Встановити необхідні пакети: `cors`, `helmet`, `express-rate-limit`, `morgan`, `winston`.
2. Налаштувати та інтегрувати `helmet` як глобальний middleware у вашому головному файлі `server.js` (або `app.js`).
3. Налаштувати `cors`. Дозволити запити лише з певних доменів (якщо відомий клієнт), або дозволити всі для спрощення на етапі розробки, але виділити це в окрему конфігурацію.
4. Налаштувати `express-rate-limit` для всіх або тільки для "чутливих" маршрутів (наприклад, `/api/auth`). Обмежити кількість запитів (наприклад, макс. 100 запитів за 15 хвилин з однієї IP-адреси).
5. Налаштувати `morgan` для логування вхідних HTTP-запитів (режим `dev` для розробки, та `combined` для production).
6. Налаштувати `winston` для логування дій сервера. Зробити так, щоб помилки записувалися у файл `logs/error.log`, а звичайні повідомлення — у консоль та файл `logs/combined.log`.
7. Інтегрувати логер `winston` у ваш глобальний обробник помилок (Global Error Handler з ЛР 2) замість звичайного `console.error`.
8. Підготувати змінні середовища та перевірити роботу додатку.

## 4. Вимоги до реалізації

### 4.1. Файлова структура (доповнення)
```
/src
  /config
      logger.js    # Налаштування winston
  /middlewares
      rate-limiter.middleware.js # Налаштування express-rate-limit
...
/.env              # Додати NODE_ENV=production або development
```

### 4.2. Приклад обмеження запитів (Rate Limiting)
При перевищенні ліміту сервер має повертати помилку 429:
```json
{
  "success": false,
  "error": "Too many requests from this IP, please try again after 15 minutes",
  "status": 429
}
```

## 5. Очікуваний результат
1. Додаток запускається та працює стабільно.
2. HTTP-заголовки відповідей містять налаштування від розширення Helmet (можна переглянути в Postman у вкладці Headers).
3. Після 100-го поспіль відправленого запиту (можна зменшити ліміт до 3-5 для тестування) API блокує IP користувача на заданий час та повертає статус `429 Too Many Requests`.
4. Всі HTTP-запити логуються у консоль. Клієнтські та серверні помилки детально записуються у файл `logs/error.log`.
5. Додаток підготовлений до розгортання в хмарі (наприклад, AWS).
