# Лабораторна робота №2: Інтеграція Бази Даних

## 1. Мета роботи
Опанувати роботу з реляційними базами даних (PostgreSQL) в середовищі Node.js, використовуючи ORM (Object-Relational Mapping). Навчитися створювати моделі даних, виконувати асинхронні операції з БД, а також реалізувати механізми глобальної обробки помилок та валідації вхідних даних (за допомогою Joi або Zod).

## 2. Теоретичні відомості
- **PostgreSQL** — об'єктно-реляційна система управління базами даних (СУБД).
- **ORM (Object-Relational Mapping)** — технологія програмування, яка пов'язує бази даних з концептами об'єктно-орієнтованих мов програмування, створюючи "віртуальну об'єктну базу даних". Популярні ORM для Node.js: `Sequelize`, `Prisma`, `TypeORM`.
- **Асинхронність (Async/Await)** — механізми JavaScript, які дозволяють виконувати операції (такі як запити до БД), не блокуючи основний потік виконання.
- **Глобальна обробка помилок (Error Handling Middleware)** — спеціальний middleware в Express (з 4 параметрами: `err, req, res, next`), який перехоплює всі помилки, надіслані через `next(err)`, і форматує єдину структуру відповіді.
- **Валідація даних** — процес перевірки вхідних даних (з `req.body`) на відповідність певним правилам та типам перед тим, як вони потраплять до бази даних. Інструменти: `Joi`, `Zod`.

## 3. Завдання
1. Розгорнути локально або у хмарі базу даних PostgreSQL.
2. Підключити до проєкту ORM (наприклад, `Sequelize` або `Prisma`) та налаштувати з'єднання з БД (параметри підключення винести у файл `.env`).
3. Створити модель (схему) `Place` у базі даних відповідно до доменної моделі. Для цього використати міграції або синхронізацію ORM.
4. Модифікувати `PlaceService` (створений у ЛР №1): замінити in-memory масив на асинхронні виклики методів ORM для виконання CRUD-операцій у таблиці `places`.
5. Створити схему валідації для створення та оновлення `Place` (за допомогою Joi або Zod) та написати Validation Middleware, який буде перевіряти `req.body` перед викликом контролера.
6. Реалізувати Error Handling Middleware: створити централізований обробник, який буде ловити помилки, логувати їх та повертати клієнту стандартизовану JSON-відповідь з кодом помилки. Переконатися, що всі контролери обгорнуті в блок `try/catch` (або `express-async-handler`), і помилки передаються через `next(error)`.
7. Протестувати оновлені API endpoints через Postman.

## 4. Вимоги до реалізації

### 4.1. Зміни в доменній моделі `Place`
Тепер сутність `Place` в БД має мати такі типи полів:
- `id` (UUID або Серійний Integer — Primary Key)
- `name` (String/VARCHAR, обов'язкове)
- `description` (Text, необов'язкове)
- `city` (String/VARCHAR, обов'язкове)
- `address` (String/VARCHAR, обов'язкове)

### 4.2. Файлова структура (доповнення)
```
/src
  /config         # Налаштування БД
  /middlewares    # Валідація та обробка помилок
      error.middleware.js
      validate.middleware.js
  /validations    # Схеми Joi/Zod
      place.validation.js
  /models         # Моделі ORM
      place.model.js
...до існуючих тек
.env              # Змінні оточення (DSN для PostgreSQL)
```

### 4.3. Приклад глобального Error Handler'а (респонс)
При виникненні помилки (наприклад, місце не знайдено) сервер має повертати стандартизований об'єкт, а не крашитися:
```json
{
  "success": false,
  "error": "Place with ID 5 not found",
  "status": 404
}
```

### 4.4. Приклад Валідації
При незаповнених обов'язкових полях під час POST/PUT запиту сервер має повернути помилку `400 Bad Request`:
```json
{
  "success": false,
  "error": "Validation error: 'city' is required",
  "status": 400
}
```

## 5. Очікуваний результат
1. Додаток успішно підключається до PostgreSQL. Таблиця `places` створюється автоматично або через міграцію.
2. Всі операції базового CRUD з ЛР №1 тепер зберігають/зчитують дані з реальної БД.
3. При передачі некоректних даних у `POST /api/places` система не падає, а повертає `400 Bad Request` із описом проблеми від валідатора (Joi/Zod).
4. Якщо в контролері/сервісі стається критична помилка або запит на неіснуюче місце, система не "зависає", а повертає `404` або `500` помилку через Glogal Error Middleware.
