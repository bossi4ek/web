# Лабораторна робота №3: Робота з пов'язаними даними (Reviews)

## 1. Мета роботи
Опанувати роботу з пов'язаними даними в базах даних за допомогою ORM. Навчитися налаштовувати зв'язки типу "один-до-багатьох" (One-to-Many). Зрозуміти принципи побудови та обробки вкладених маршрутів (nested routes) в REST API для роботи з залежними сутностями.

## 2. Теоретичні відомості
- **Зв'язки в БД** — зв'язки між таблицями або моделями. Основні типи: "один-до-одного" (1:1), "один-до-багатьох" (1:N), "багато-до-багатьох" (M:N).
- **Зовнішній ключ (Foreign Key)** — колонка або декілька колонок в одній таблиці, що вказують на первинний ключ (Primary Key) в іншій таблиці, забезпечуючи зв'язок між ними.
- **Вкладені маршрути (Nested Routes)** — підхід до проєктування REST API, де URL відображає ієрархію ресурсів. Наприклад, відгуки належать конкретному місцю, тому логічним є маршрут `/api/places/:placeId/reviews`.
- **Express `mergeParams`** — опція в Express Router (`express.Router({ mergeParams: true })`), яка дозволяє дочірньому роутеру отримувати доступ до параметрів (наприклад, `:placeId`) з батьківського роутера.

## 3. Завдання
1. Створити модель `Review` у вашій ORM згідно з доменною моделлю.
2. Налаштувати зв'язок типу "один-до-багатьох" (1:N) між моделями `Place` та `Review` (одне місце може мати багато відгуків, один відгук належить одному місцю).
3. Додати валідацію для моделі `Review` (рейтинг має бути числом від 1 до 5, коментар — текстом).
4. Налаштувати вкладений роутер для відгуків, щоб зробити їх прив'язаними до конкретного `Place`.
5. Реалізувати контролери та сервіси для створення відгуку для конкретного місця та отримання списку відгуків для цього місця.
6. Протестувати нові endpoints за допомогою Postman. Окремо перевірити, чи видаляються відгуки при видаленні самого місця (каскадне видалення — `ON DELETE CASCADE`), якщо ви це налаштуєте.

## 4. Вимоги до реалізації

### 4.1. Доменна модель `Review`
- `id` (UUID або Серійний Integer — Primary Key)
- `rating` (Integer, обов'язкове, від 1 до 5)
- `comment` (Text, обов'язкове)
- `placeId` (Foreign Key на таблицю `places`, обов'язкове)

### 4.2. Файлова структура (доповнення)
```
/src
  /controllers
      review.controller.js
  /services
      review.service.js
  /routes
      review.routes.js
  /validations
      review.validation.js
  /models
      review.model.js
...
```

### 4.3. API Endpoints
Необхідно реалізувати наступні маршрути:
- `GET /api/places/:placeId/reviews` — отримати всі відгуки для конкретного місця.
- `POST /api/places/:placeId/reviews` — створити новий відгук для конкретного місця.

Також можна додати (опціонально):
- `DELETE /api/reviews/:id` — видалити відгук за його власним id.

*Приклад відповіді на POST запит створення відгуку:*
```json
{
  "success": true,
  "data": {
    "id": "1",
    "rating": 5,
    "comment": "Чудове місце для прогулянок!",
    "placeId": "123e4567-e89b-12d3-a456-426614174000"
  },
  "status": 201
}
```

## 5. Очікуваний результат
1. У базі даних успішно створено таблицю `reviews` із зовнішнім ключем на таблицю `places`.
2. Реалізовано можливість додавати відгуки до конкретного місця за допомогою виклику `POST /api/places/:placeId/reviews`.
3. Виклик `GET /api/places/:placeId/reviews` повертає список відгуків, що належать тільки вказаному місцю.
4. Спроба додати відгук з некоректним рейтингом (наприклад, 6 або з текстовим значенням) викликає помилку валідації (`400 Bad Request`).
5. Спроба додати відгук для `placeId`, якого не існує в базі даних, повертає помилку (`404 Not Found`).
