# 📚 Концепція курсу: Backend розробка (Places / Locations API)
**Цільова аудиторія:** Студенти 3 курсу  
**Формат:** 6 базових лабораторних робіт + 1 додаткова (advanced). Наскрізний проєкт.

## 🌟 1. Ключова ідея курсу
Всі лабораторні роботи є етапами розробки єдиного програмного продукту — REST API для роботи з місцями (Places). Кожна наступна лабораторна робота логічно розширює функціональність попередньої. 

Після завершення курсу студенти повинні вміти:
- Проєктувати та розробляти REST API.
- Працювати з екосистемою Node.js та Express.
- Будувати правильну архітектуру backend-додатку (Layered architecture: controllers, services, repositories).
- Інтегрувати базу даних (PostgreSQL).
- Реалізовувати безпеку (Аутентифікація/Авторизація через JWT).
- Обробляти помилки та готувати додаток до деплою.

---

## 🎯 1.1. Опис наскрізного проєкту (Places API)
Протягом курсу студенти створюють єдиний продукт — **платформу для обміну цікавими локаціями (Places/Locations API)**. Це бекенд для додатку, що нагадує спрощений TripAdvisor або Foursquare.

**Основні сценарії використання (Business Logic):**
- **Перегляд контенту:** Будь-який користувач (навіть гість) може переглядати каталог місць, читати детальний опис, бачити адресу та читати відгуки інших людей.
- **Управління місцями:** Після реєстрації та авторизації користувач може створювати нові локації на платформі (ділитися своїми знахідками), а також редагувати чи видаляти **свої** місця.
- **Соціальна взаємодія:** Авторизовані користувачі можуть залишати коментарі та ставити оцінки (1-5 зірок) закладам чи локаціям.
- **Модерація:** Система підтримує рольову модель. Користувачі з роллю `admin` мають права на управління всім контентом (видалення будь-яких місць або відгуків у разі порушення правил).
- **Пошук:** Реалізована можливість фільтрації місць (наприклад, за містом) та пагінація для зручного перегляду великих списків.

## 🛠 2. Технологічний стек
- **Основні технології:** Node.js, Express.
- **База даних:** PostgreSQL.
- **Безпека:** JWT (JSON Web Tokens).
- **Інструменти:** Git, Postman, VS Code (або будь-який редактор коду).

---

## 🧩 3. Доменна модель (Базова схема БД)
- **User:** `id`, `email`, `password` (hashed), `role` (user/admin)
- **Place:** `id`, `name`, `description`, `city`, `address`, `createdBy` (User ID)
- **Review:** `id`, `rating` (1-5), `comment`, `userId` (User ID), `placeId` (Place ID)

---

## 📅 4. План лабораторних робіт

### 🔹 ЛР 1: Основи backend + Places API (In-memory)
**Фокус:** Node.js, Express, базові REST API принципи.  
**Результат:** Реалізовано базовий CRUD для сутності `Place` (збереження в пам'яті). Структуровано проєкт.

### 🔹 ЛР 2: Інтеграція Бази Даних
**Фокус:** Підключення ORM/ODM, асинхронна робота з БД, глобальна обробка помилок, базова валідація даних (напр. Joi / Zod).  
**Результат:** Дані сутності `Place` зберігаються в БД. Реалізовано централізований Error Handler. Вхідні дані валідуються перед збереженням.

### 🔹 ЛР 3: Робота з пов'язаними даними (Reviews)
**Фокус:** Реляції між таблицями/колекціями, вкладені маршрути.  
**Результат:** Додано сутність `Review`. Можливість залишати відгуки до конкретних місць та виводити їх списком.

### 🔹 ЛР 4: Аутентифікація та JWT
**Фокус:** Реєстрація, логін, хешування паролів, захист API.  
**Результат:** Реалізовано сутність `User`. Маршрути створення/редагування місць та відгуків захищені токеном.

### 🔹 ЛР 5: Просунуті запити (Фільтрація, Пагінація, Ролі)
**Фокус:** Обробка Query Params, RBAC (ролі).  
**Результат:** Пошук місць за містом/рейтингом, пагінація сторінок. Додано роль `admin`.

### 🔹 ЛР 6: Production Readiness
**Фокус:** Логування (Winston/Morgan), безпека (Helmet, CORS, Rate Limiting), підготовка до деплою.  
**Результат:** Додаток генерує логи, захищений від базових атак та готовий до розгортання.
